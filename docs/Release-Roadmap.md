# GlassOps 版本路线图

规划日期为 2026 年 11 月 26 日。基线为 GitHub `main` 与 `v1.0.11` 对应的提交 `54d559c`，目标后端为 Komari 1.6.2。本地 checkout 尚停留在 v1.0.8，开始开发时从基线建立独立工作分支，以保留本地工作。

## 发布顺序

| 次序 | 建议版本 | 主题                     | 变更性质                                             | 进入下一阶段的条件                                                                            |
| ---- | -------- | ------------------------ | ---------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 1    | `v1.1.0` | 图表修正与多节点线路对比 | 修复 Ping 和网络图表，扩展现有对比面板，补齐列表排序 | Komari 1.6.2 上最新探测状态和长周期聚合通过回归。同任务、同时间窗的多节点统计与单节点详情一致 |
| 2    | `v1.2.0` | 账期流量与余量预测       | 在现有配额与健康面板加入周期计算                     | 跨账期、计数器重置、历史截断和数据缺失时均有明确结果                                          |
| 可选 | `v1.3.0` | 掉线与恢复记录           | 在详情页展示新增的事件数据                           | 有可验证的服务端事件源与采集覆盖后再定版                                                      |

原 `v1.0.12` 的图表修正与原第二次迭代合并到 `v1.1.0`。这两项共用同一套历史数据口径，按顺序开发验证，一起发布。账期流量单独验证，掉线历史视事件数据来源再排期。发布前按 GitHub 最新标签核对版本号。

## 第一次 · v1.1.0 图表修正与多节点线路对比

### 1. 校正已有图表

- 首先修正详情 Ping 的「最新」。本次成功时显示延迟，本次失败时显示「丢包」，采集状态无法确认时显示「暂无数据」。上次成功延迟可独立显示，并带时间。
- 核对长周期上传和下载速率以及「峰值」类标签。标明均值与峰值各自的聚合口径，峰值使用后端可校验的数据。遇到缺失时显示缺省状态。
- 验收覆盖最后一条丢包、全段丢包、无采样、图表聚合及旧接口回退。确认换时段后标题和统计一致，首页至详情及返回路径正常。

### 2. 在现有对比面板增加线路对比

- 首页「对比」面板内提供「实时快照」与「线路对比」页签，共用现有节点选择。选择 2–4 台节点后，按同一探测任务 ID 筛选共同任务，每次对比一个任务。时间支持近 1 小时、近 6 小时、近 24 小时与自定义，默认近 6 小时。
- 延迟图最多 4 条曲线，每台节点用固定颜色和线型区分。每台节点有一行与延迟图同时间轴的丢包时间条，文字或图例区分正常、丢包和无样本。统计逐节点展示丢包率、后端返回的 P50/P99 与有效／总样本数。空值、任务未绑定和无共同任务分别提示。
- 桌面端依次展示筛选、延迟图、丢包时间条与汇总。手机端筛选可折行，按节点纵向显示统计，支持点按查看图表数值。
- 验收场景为同一任务下，对比东京和美西昨晚 20–23 点的表现，并与各自详情核对。另覆盖四节点、没有共同任务、部分节点缺样、快速切换时段和访客可见性。
- 界面参考：[Next Pro 网络总览原图](https://github.com/fanchengliu/komari-next-pro/blob/v3.0.1/docs/images/network.png) 用于筛选、同时间窗曲线、丢包时间条和逐项汇总。参考 [PingPlotter 时间轴](https://www.pingplotter.com/fix-your-network/getting-started/timeline-graphs/) 的丢包提示，复用 GlassOps 的现有控件与配色。

### 3. 补齐列表排序

- 对现有列表增加 CPU、内存、磁盘和流量配额使用率排序。验证升降序、无限配额和缺数据节点，以及访客原有的节点与价格可见规则。

## 第二次 · v1.2.0 账期流量与余量预测

- 在现有流量详情和健康摘要中提供每节点重置日、时区、本期已用与剩余额度、距重置的天数。按节点已有配额口径计算。
- 历史覆盖足够时，用近期日用量估算耗尽日期。将估算依据与观测覆盖一同展示。未配置账期、无限配额、数据不足和中途重启分别处理。
- 验收覆盖不同重置日与时区、月末短月、多个配额口径、跨账期、计数器重置及历史只覆盖部分账期。先跑通只读流程，再根据使用需求决定是否引入用量校准。

## 可选 · v1.3.0 掉线与恢复记录

- 第一版在节点详情展示已记录的掉线、恢复和时长。具备足够观测覆盖时加入 30 天在线率，并展示覆盖天数。区分 Agent 断连、采集缺失与业务探测失败。
- 使用服务端可验证的事件来源，例如兼容的 Availability History 插件。先验证有插件、无插件、首次启用与 Komari 重启四类情形，再锁定版本。尚未具备事件源时保持待定。

## 兼容维护与后续小项

- Komari 1.6.2 已走官方后台。需要恢复内嵌后台时单独安排维护版，使用匹配的官方 1.6.2 前端资源，验证登录、设置保存、终端恢复、日志筛选和旧入口回退。维护版按当时最新发布版本编号。
- 数据最后同步时间可作为后续小更新，沿用当前断连提示。续费 30／90 天筛选可排在费用明细小更新，地球性能根据贴图体积和首屏实测决定。
- 每个代码版本跑 `bun run lint`、`bun run build`、`bun run test:visual`。在隔离的 Komari 1.6.2 验证导入和本版关键路径，覆盖桌面和移动端。发布后复核 GitHub Actions、Release 和 ZIP。
